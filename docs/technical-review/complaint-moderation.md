# 신고 검토와 원본 조치 및 결과 전달을 한 흐름으로 관리

신고 관리는 상태만 완료로 바꾸는 기능이 아니다. 같은 대상을 여러 사용자가 신고할 수 있고, 관리자 둘이 동시에 처리할 수 있으며, 원본 콘텐츠 조치와 신고자·피신고자 안내가 서로 어긋날 수 있다. 현재 구현은 신고 검토, 원본 조치, 이용정지와 결과 생성을 하나의 관리자 흐름에서 다룬다.

## 조회와 검토 상태

관리자는 상태·대상 유형·사유·접수 기간·신고자 조건으로 저장된 신고를 검색한다. 상세 화면은 선택한 신고뿐 아니라 같은 대상의 신고, 현재 피신고자 정보와 자동 조치 진행 상태를 함께 보여준다. 보존기간이 남은 이미지 증거 원본은 관리자 인증을 통과한 요청에만 제공한다.

신고 상태는 접수에서 검토 중으로, 검토 중에서 조치 완료 또는 반려로만 이동한다. 검토를 시작한 관리자를 담당자로 기록하고, 최종 처리는 담당자 또는 최고 관리자만 할 수 있다.

## 동시 처리

`ComplaintServiceImpl`은 수정 전에 신고 행을 잠그고 화면이 조회한 수정 시각과 최신 값을 비교한다. 다른 관리자가 먼저 처리했다면 오래된 요청을 충돌로 반환한다. 상태 전이와 처리 메모도 같은 트랜잭션에서 검증한다.

## 대상별 원본 조치

원본을 다루는 방식은 데이터 구조에 맞춰 구분한다.

| 대상 | 관리자 조치 |
| --- | --- |
| 독후감 | 연결 데이터를 정리한 뒤 원본 완전 삭제 |
| 댓글 | 계층 관계를 유지하며 삭제 상태로 전환 |
| 프로필·배경 이미지 | 사용자 참조와 파일 메타정보 제거 후 기본 이미지 적용 |
| 한줄소개·모임 소개 | 관계 데이터는 유지하고 소개 내용 초기화 |
| 사용자 | 일반 사용자 관리와 같은 이용정지·해제 흐름 사용 |

하나의 원본 조치로 해결되는 동일 대상의 미처리 신고는 함께 종결한다. 이미지 파일은 데이터베이스 커밋이 끝난 뒤 삭제해 롤백된 사용자 참조가 사라진 파일을 가리키지 않도록 한다.

## 결과 공개 범위

조치 완료 시 신고자와 피신고자가 확인할 결과 이벤트를 만든다. 내부 관리자 메모, 정확한 누적 건수와 정지 기간은 공개하지 않는다. 피신고자에게는 단일 사유, 복수 사유 또는 기타 사유처럼 필요한 범위만 요약하고 실제 콘텐츠 조치 결과를 한국어와 영어로 저장한다.

## 현재 범위

관리자 프로젝트의 조회·검토·원본 조치·결과 전달은 구현되어 있다. 사용자 앱에서 신규 신고를 저장하는 API 연결은 현재 한계로 남아 있으므로, 실제 사용자 신고 접수부터의 전체 흐름은 그 연결이 완료된 뒤 통합 검증해야 한다.
