# 배치 실행과 관리자 관찰 책임을 분리

회원 상태 동기화와 영구 삭제 같은 배치는 사용자 백엔드가 실제 업무 데이터와 세션 상태를 알고 있다. 관리자가 실행 책임까지 가지면 같은 배치 로직이 두 서비스에 나뉘고, 운영 화면이 새로운 실패 지점이 될 수 있다. 현재 구조는 사용자 서비스가 배치를 실행하고 관리자 프로젝트는 결과를 읽기 전용으로 조회한다.

## 조회 범위

`ScheduleLogServiceImpl`은 로그인 관리자를 확인한 뒤 검색 조건에 맞는 실행 목록을 페이지 단위로 반환한다. 상세 화면에서는 실행 상태, 시작·종료 시각, 처리·성공·실패 건수와 소요 시간을 확인할 수 있다. 실패한 작업은 같은 실행에 연결된 실패 상세 목록으로 분리해 조회한다.

실행 번호가 없거나 유효하지 않으면 조회를 거부하고, 부모 실행 기록이 없으면 빈 상세를 만들지 않고 명시적인 조회 실패로 처리한다.

## 책임 경계

관리자 API에는 배치를 시작하거나 로그를 수정하는 메서드가 없다. 사용자 서비스가 실행과 기록을 소유하고, 관리자 서비스는 관찰과 문제 확인만 담당한다. 이 구분은 관리자 화면 장애가 배치 실행에 영향을 주지 않게 하고, 운영자가 결과를 수정해 실제 실행 이력과 달라지는 상황을 막는다.

## 실패 정보

실패 상세는 원시 예외 전체를 관리자 화면에 노출하기 위한 저장소가 아니다. 대상과 대표 실패 원인을 확인할 수 있는 운영 정보로 사용한다. 비밀값과 개인정보가 예외 메시지에 포함되지 않도록 배치 기록 단계에서도 정제가 필요하다.

## 한계와 개선점

현재 구조는 저장된 실행 결과를 조회하는 기능에 집중한다. 배치 지연, 연속 실패와 처리량 이상을 자동으로 알리는 경보는 별도 영역이다. 운영 규모가 커지면 최근 성공 시각, 실패율과 처리 지연을 지표로 집계하고 임계치를 넘을 때 알림을 보내는 기능을 추가할 수 있다.
